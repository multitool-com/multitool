## 📐 ARQUITETURA DE CADA FERRAMENTA

Cada ferramenta segue o padrão de 2 arquivos:

### 1. `page.tsx` (Server Component)
Responsabilidades:
- Exporta `metadata` completa (title, description, keywords, canonical, OG, Twitter)
- Renderiza `<ToolLayout>` com todas as props
- Renderiza o `<ClientComponent>` como children

Props do ToolLayout:
```tsx
title: string              // Ex: "Word Counter"
description: string        // Descrição curta
categoryName: string       // Ex: "Text Tools"
categorySlug: string       // Ex: "text-tools"
toolSlug: string           // Ex: "word-counter"
children: React.ReactNode  // O ClientComponent
howItWorks?: React.ReactNode // JSX longo educativo (SEO + AdSense)
faqs?: FAQ[]               // Array com 6 perguntas { question, answer }
relatedTools?: RelatedTool[] // Array com 4 ferramentas { name, href }
```

### 2. `[Nome]Client.tsx` (Client Component)
Responsabilidades:
- `"use client"` no topo
- Toda a lógica interativa (useState, useMemo)
- UI completa com inputs, botões, visor, breakdown
- Sub-componente `StatBlock` para cards de resultado
- Validação: retorna null quando input inválido
- Multi-moeda quando aplicável (USD/EUR/GBP/BRL)
- Formatação: `toLocaleString()` com 2-4 casas decimais

### Padrão do `howItWorks`:
- Contém 3-6 seções com `<h2>` e `<p>`/`<ul>`
- Inclui fórmulas, exemplos práticos, referências
- SEMPRE termina com seção "Your privacy" (bom para AdSense)
- Usa classes: `bg-paper border border-ink/10 rounded-lg p-4 my-3` para blocos de código/fórmula

### Padrão das FAQs:
- Array de 6 objetos `{ question: string, answer: string }`
- Respondem dúvidas comuns do usuário
- Renderizadas com `<details>/<summary>` pelo ToolLayout
- Geram schema JSON-LD FAQPage (SEO)

### Padrão dos Related Tools:
- Array de 4 objetos `{ name: string, href: string }`
- hrefs são relativos: `/tools/[category]/[tool]`
- SEMPRE apontam para ferramentas da MESMA categoria
